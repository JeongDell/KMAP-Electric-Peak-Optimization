# 최대수요전력 예측과 피크 관리 — 소스코드

선박엔진용 볼트·너트 공장의 15분 전력을 1시간~4일 앞까지 예측한다. 그 예측으로 이번 달 최고 전력(요금적용전력)에 다가가는 날과 시간을 미리 알리고, 피크를 낮추는 부하 이동 방안을 계산한다.

**`전체실행.ipynb`를 위에서부터 실행하면 결과보고서의 숫자를 다시 만든다.** 무거운 재학습은 기본으로 꺼져 있다. 그래서 CPU 노트북에서 약 5분 걸린다.

## 1. 빠른 실행

```bash
# 1) 노트북 기본 실행 환경 (Python 3.12에서 확인. torch는 CPU 판으로 충분)
python -m pip install -r requirements.txt

# 2) 제출 폴더 최상위(이 README가 있는 곳)에서 노트북 실행
jupyter notebook 전체실행.ipynb        # 메뉴에서 Run All
```

- 노트북은 각 단계의 `.py` 파일을 순서대로 단독 실행한다. 단계 코드를 직접 실행해도 결과는 같다(예: `cd 1_전처리/5_코드` → `python 1.1_시간복원.py`).
- 모든 경로는 `paths.py` 한 파일에서 정한다. 폴더를 통째로 옮겨도 고칠 곳이 없다.
- 각 단계의 결과는 단계 폴더의 `3_최종데이터/`(다음 단계가 읽는 확정 결과)와 `6_중간산출물/`(csv·로그)에 저장된다.

|---|---|

| `2_딥러닝/data/timeseries_15min_v1_previous_week.csv` | 트리·딥러닝 모델이 학습에 쓴 팀 공통 15분 파일. 노트북 1-1에서 위 확정 데이터와 칸마다 대조한다 |

모델 입력 파일과 전처리 확정 파일은 시각·전력·기상·인건비·요금·주야·요일 값이 같다. 다른 점은 세 가지다(노트북 1-1에서 확인).
- 달력 칸: 모델 입력은 `day_type`(0 평일, 1 토, 2 일, 3 공휴일) 하나로 줄였다. 모델 입력의 `day_type` 3에는 공휴일 10일 외에 8/2~8/6(생산량이 0인 평일 5일)도 들어 있다. 우리 전처리 달력에서는 이 5일이 평일이다.
- 7/13·7/15 생산량: 모델 입력(v1)은 전주 같은 시각 값이다.
- `공장인원` 칸: 모델 입력에만 있다. 딥러닝은 이 칸을 입력으로 쓰지 않는다(그날이 돼야 아는 실측값이라서, `2_딥러닝/core/data.py`).

## 5. 결과 파일

### 제출 예측결과 파일 (9월 시험)

`2_딥러닝/test_predictions/(구간).csv` 6개. 노트북 마지막 칸이 `결과/9월_시험예측/`에도 복사한다. 한 줄은 한 발행 시각에서 예측한 15분 칸 하나다.

| 열 | 뜻 |
|---|---|
| `model`, `loss`, `horizon` | 모델(ENSEMBLE = 세 모델 평균), 학습 손실(A = RMSE, C = 피크 가중 손실), 예측 구간 |
| `seed` | 시드 평균 정보. 앙상블은 `mean(세 모델)`(각 모델은 시드 3개 평균) |
| `period` | 평가 기간 (모두 `9월`) |
| `origin`, `lead`, `target_time` | 발행 시각, 몇 번째 15분 칸인지(1부터), 대상 시각 |
| `y`, `yhat` | 실제 전력, 예측 전력 (kW) |
| `b_origin` | 발행 시점의 피크 기준 b = max(170kW, 그달 발행 전까지 최고) |
| `대표` | `A 최고` 또는 `C 최고` |

**보고서의 최종 모델은 구간마다 아래 행이다.**

| 구간 | 최종 모델 | 파일에서 고를 행 |
|---|---|---|
| 1h · 4h · 8h · 12h · 24h | 딥러닝 앙상블, 피크 가중 손실 | `loss == "C"` (`대표 == "C 최고"`) |
| 4d | 딥러닝 앙상블, RMSE 손실 | `loss == "A"` (`대표 == "A 최고"`) |

| 단계 | 언어·주요 라이브러리 | 하드웨어 | requirements |

- 노트북 기본 실행(재학습 끔)은 첫 줄의 환경 하나로 처음부터 끝까지 돈다.
- 트리 학습은 별도 환경(Python 3.13.5)이 필요하다. 그래서 노트북 안에서 실행하지 않는다.
- 딥러닝 학습 환경은 학습 서버의 값이다. `2_딥러닝/README.md`에 적힌 환경(Python 3.14.7, torch CPU)은 `--resume` 재현을 확인한 컴퓨터의 값이다. `requirements_딥러닝.txt`는 버전을 고정하지 않았다(`torch>=1.10` 등).

## 7. 분석 조건

- **다앎 가정.** 미래 시점의 생산량·기상은 실제값을 생산계획·일기예보로 안다고 가정했다. 따라서 성능은 실제 운영 성능의 상한으로 본다.
- **기간 역할.** 1~6월로 학습하고 7월로 모델과 마진을 골랐다. 1~7월로 다시 학습한 최종 모델로 8월을 확인했다. 9월(1~14일)은 고르기·조정에 쓰지 않은 평가 기간이다. 9월에는 재학습하지 않았다.
- **4일 예측.** 결과는 참고로 싣는다. 8월에 기준선보다 나빠서 현장 활용(경보)에는 쓰지 않는다.
- **7/13·7/15.** 기상 시각만 복원되고 전력에 결함이 남은 날이라 마진·경보 평가에서 뺐다.

## 8. 읽는 법

- 코드와 표에서 **'동수' = 딥러닝 앙상블, '정현' = 트리 앙상블**이다(만든 팀원 이름으로 구분).
- 코드 주석과 팀원 README에 나오는 `진행상황/…`, `팀원 작업물/…`, `5번_분석/…`, `experiments/…`, `../ensemble/…` 같은 경로는 원래 작업 폴더의 위치다. 제출 묶음에서는 이 위치를 쓰지 않고, 실제 경로는 모두 `paths.py`에서 정한다.
- `2_딥러닝/README.md`는 딥러닝 폴더만의 설명이다. 그 안의 폴더 그림 최상위 `final/`은 제출 묶음의 `2_딥러닝/`이고, `data/`는 팀 공통 15분 입력 파일이다.
