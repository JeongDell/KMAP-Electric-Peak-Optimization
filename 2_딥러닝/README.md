# 전력 예측 제출 코드

RNN·LSTM·N-HiTS로 15분 단위 전력(`power_15min`, kW)을 1h·4h·8h·12h·24h·4d 앞까지 예측한다. 7월 성적으로 모델 설정·대표·안전마진을 정하고, 1~7월로 학습한 최종 모델로 8월에 확인 검증한 뒤, 같은 모델·대표·마진으로 9월(1~14일)을 테스트한다.

## 주요 결과

포함된 결과(`results/future_known/`) 기준이다. 전체 수치는 `results_summary.csv`에 있다. 용어는 바로 아래 「용어」 참고.

- **대표**: 12개(구간 6 × 손실 A·C) 모두 ENSEMBLE(세 모델 평균 예측)이 7월 공통 C 1위로 선정되었다.
- **9월 테스트**: 대표의 RMSE는 8.6~10.8 kW이며, 6개 구간 모두 가장 좋은 기준선(지난주)보다 공통 C가 낮다 (A 최고 7~23%, C 최고 4~23%).
- **8월 확인**: 1h~12h는 가장 좋은 기준선보다 3~38% 나았지만, 24h·4d는 기준선(비슷한날)보다 17~29% 나빴다. 8월에는 휴무·재가동 주(8/2~8/13)가 들어 있다. 정해 둔 규칙대로 대표는 바꾸지 않았다.
- **손실 C의 효과**: C 최고가 A 최고보다 공통 C에서 유의하게 나은 경우는 8월 1h·4h, 9월 4h·12h·24h이며, 이때 RMSE 손해는 유의하지 않았다. 나머지는 차이가 유의하지 않았다. 9월 4d는 A가 나았으나 발행이 11개뿐이라 해석을 보류했다.
- **안전마진 경보**: 7월 오차로 정한 마진(b의 26~39%)이 8월·9월 모두 12/12 합격했다 (피크 근처 날 8월 7일 중 6~7일, 9월 10일 모두 미리 경보, 하루 헛경보 1번 이하). 다만 경보 선이 낮아 경보가 켜져 있는 시간이 하루 6~12시간(8월), 10~20시간(9월)이다.
- **조건**: 미래 생산량·날씨의 실제값을 아는 다앎 조건의 결과이므로, 실제 운영 성능의 상한으로 봐야 한다.

공통 C 개선율 (같은 구간·달에서 가장 좋은 기준선 대비, %, `A 최고 / C 최고`. 음수 = 기준선보다 나쁨)

| 구간 | 7월 선정 | 8월 확인 | 9월 테스트 |
|---|---|---|---|
| 1h | 33.0 / 34.9 | 36.4 / 38.1 | 22.8 / 23.2 |
| 4h | 17.0 / 19.6 | 19.0 / 28.7 | 11.1 / 13.8 |
| 8h | 10.0 / 15.0 | 13.0 / 14.8 | 11.4 / 11.9 |
| 12h | 9.4 / 11.6 | 3.3 / 3.8 | 10.3 / 13.1 |
| 24h | 6.3 / 9.1 | −17.1 / −22.7 | 7.4 / 11.3 |
| 4d | 11.3 / 5.8 | −29.0 / −26.6 | 9.8 / 3.6 |

가장 좋은 기준선: 7월·9월은 모든 구간에서 지난주, 8월은 1h 직전값·나머지 비슷한날. 경보 수치는 `results/future_known/margin/③8월_검증.csv`·`④9월_시험.csv`의 `주결과` ✓ 행(전체 기간), 손실 C 효과는 `results/future_known/significance/ac_decision.csv`에 있다.

## 용어

| 용어 | 뜻 |
|---|---|
| 구간 (1h~4d) | 한 번에 내다보는 길이. 15분 칸 4·16·32·48·96·384개 |
| 발행 | 예측을 내는 시점(`origin`). 채점은 1h는 15분마다, 4h~24h는 1시간마다, 4d는 하루마다 발행한 예측으로 한다 |
| 피크 기준 b | max(170 kW, 발행 시점까지 그 달에 관측된 최대 전력). 미래 값은 쓰지 않는다 |
| 손실 A | 학습 손실 = RMSE |
| 손실 C | 0.5 × L_mean + 0.3 × L_CVaR + 0.2 × L_peak. 예측 구간을 블록(1h~24h는 1시간, 4d는 1일)으로 나눠 블록별 RMSE를 구하고, L_mean = 그 평균, L_CVaR = 가장 나쁜 20% 블록의 평균, L_peak = 과소예측(실제 > 예측)만 센 오차로 실제가 0.8b를 넘을수록 가중치가 커져 b 이상에서 2배 |
| 공통 C | 손실 C와 같은 식으로 잰 평가 지표(kW). A로 학습한 후보와 기준선까지 같은 잣대로 비교하며, 설정·대표 선정에 쓴다 |
| A 최고 / C 최고 | 손실 A(또는 C)로 학습한 후보(RNN·LSTM·N-HiTS·ENSEMBLE) 중 7월 공통 C가 가장 낮은 것. 구간·손실별 대표 |
| ENSEMBLE | 같은 손실로 학습한 RNN·LSTM·N-HiTS 예측의 평균. 각 모델은 시드 3개(42·43·44) 예측의 평균 |
| 기준선 | 학습 없이 만드는 비교 대상 4개: 직전값(발행 직전 15분 값 유지), 어제 같은 시각, 지난주 같은 시각, 비슷한날(같은 날 종류의 최근 4일 같은 시각 중앙값) |
| 피크 근처 | 실제 전력이 0.9b 이상인 칸 |
| 안전마진·경보 | 예측이 (0.9 − 마진) × b 이상이면 경보. 마진 = 7월 피크 근처 칸의 과소예측량(실제 − 예측, b 대비)의 95% 지점 |
| 경보 합격 기준 | 피크 근처가 있었던 날의 80% 이상을 미리 경보하고, 하루 헛경보가 1번 이하 |
| 다앎 조건 | 미래 시점의 실제 생산량·날씨를 입력으로 쓰는 조건 |

## 1. 폴더 구조

```text
final/
├── README.md              이 문서
├── requirements.txt       필요 패키지
├── main.py                전체 실행 (학습 → 선정 → 재학습 → 확인 검증 → 테스트 → 제출 파일 저장)
├── config.py              설정 (데이터 경로, 모델·그리드, 시드, 기간, 학습)
├── core/                  구현 (데이터 처리·학습·마진·평가·결과 저장)
├── models/                RNN·LSTM·N-HiTS 모델
├── data/                  원자료 CSV
├── test_predictions/      ★ 제출 예측: 1h.csv, 4h.csv, 8h.csv, 12h.csv, 24h.csv, 4d.csv
├── results_summary.csv    ★ 성능 요약
└── results/
    ├── run_settings.json  --resume 때 데이터·설정을 대조하는 기록
    └── future_known/      포함된 학습 결과 (「3. 결과 파일 안내」)
```

## 2. 실행 방법

이 폴더에서 실행한다. 패키지는 `python -m pip install -r requirements.txt`로 설치한다 (안 되면 「6. 설치 상세 및 오류 해결」).

| 목적 | 명령 | 학습 |
|---|---|---|
| 포함된 결과로 검증·테스트·제출 파일 재현 | `python main.py --resume` | 하지 않음 (CPU에서 약 1분) |
| 처음부터 새로 학습해 재현 | `python main.py` | 전체 (GPU에서도 수 시간) |
| 중단된 새 학습 이어서 실행 | `python main.py --resume results/run_실행시각` | 남은 학습만 |

> `python main.py`는 포함된 결과를 쓰지 않고 **항상 새로 학습**한다. 학습 없이 결과를 확인하려면 `--resume`을 쓴다.

`--resume`은 포함된 결과와 같은 파일을 같은 내용으로 다시 만든다 (모든 출력 파일이 포함된 결과와 같음을 확인). 새 학습은 장치(GPU·CPU)와 torch 버전에 따라 학습 결과가 조금씩 달라질 수 있어, 포함된 결과와 숫자가 똑같이 나오지 않을 수 있다.

실행 화면에 표시되는 단계는 다음과 같다. 중간에 설정을 바꾸거나 다른 Python 파일을 따로 실행할 필요가 없다.

| 화면 표시 | 하는 일 |
|---|---|
| `[1/6]` | 원자료·설정 점검 → 그리드 후보 학습(1~6월) → 7월 공통 C로 모델·손실별 설정 선정 → 고른 설정을 시드 3개로 반복 학습 |
| `[2/6]` | 고른 설정을 1~7월 데이터로 다시 학습 (최종 모델) |
| `[3/6]` | 7월 공통 C로 정한 대표(A 최고·C 최고)와 7월 오차로 만든 안전마진을 고정하고, 최종 모델로 8월 확인 검증 |
| `[4/6]` | 같은 최종 모델·대표·마진으로 9월 테스트와 통계 검정. 대표나 마진이 바뀌면 오류로 멈춘다 |
| `[5/6]` | 제출용 테스트 예측 CSV와 성능 결과 저장 |
| `[6/6]` | 제출 파일의 누락·중복과 예측값 검사 |

대표와 마진은 7월 성적만으로 정한다. `[3/6]`에서 화면에 "대표 및 안전마진 확정"이라고 나오는 것은 8월 결과로 고른다는 뜻이 아니라, 이때 정한 값을 9월까지 바꾸지 않는다는 뜻이다.

기본 실행은 **새 학습부터 시작**한다. 기존 결과를 덮어쓰지 않고 `results/run_실행시각/` 아래에 새 학습 기록을 저장한다. 전체 설정은 그리드 학습 768개, 추가 시드 학습 72개, 최종 모델 학습 108개이며, 각 학습은 조기 종료로 최고 에폭을 찾은 뒤 해당 기간 전체로 다시 학습하는 두 단계로 수행한다. CUDA를 사용할 수 있으면 GPU, 없으면 CPU에서 실행한다.

검사가 통과하면 최상위 `test_predictions/`와 `results_summary.csv`를 이번 실행의 결과로 갱신한다. 압축 파일은 자동으로 만들지 않는다.

`--resume`으로 재개할 때 데이터·모델 구현·학습 설정을 저장 기록과 대조한다. 설정이 달라지면 기존 결과 재사용을 차단한다. 새 결과 경로를 직접 정하려면 `python main.py --output-dir results/new_run`을 사용할 수 있다.

## 3. 결과 파일 안내

### 제출 예측 `test_predictions/*.csv`

테스트 CSV의 한 행은 한 발행에서 예측한 15분 칸 하나이다. 손실 A와 C의 대표를 각각 포함한다. 포함된 결과에서는 12개 대표가 모두 ENSEMBLE이다 (대표는 7월 성적으로 정하므로, 새로 학습하면 RNN·LSTM·N-HiTS가 될 수도 있다).

| 열 | 의미 |
|---|---|
| `model`, `loss`, `horizon` | 대표 모델, 학습 손실, 예측 구간 |
| `seed` | 시드·모델 평균 정보 (ENSEMBLE은 `mean(세 모델)`) |
| `period` | 테스트 평가 월 (`9월`) |
| `origin` | 예측 발행 시각 |
| `lead` | 15분 칸 번호. 1은 발행 시각에 시작하는 칸 |
| `target_time` | 대상 시각: `origin + 15분 × (lead-1)` |
| `y`, `yhat` | 실제 전력 및 예측 전력 (kW) |
| `b_origin` | 발행 시점의 피크 기준 (kW) |
| `대표` | A 최고 또는 C 최고 |

### 성능 요약 `results_summary.csv`

구간·달·후보마다 한 행이다. 9월 대표 성능만 보려면 `역할`이 `시험`이고 `최고`가 비어 있지 않은 행(구간 6개 × 손실 2개 = 12행)을 고른다.

| 열 | 의미 |
|---|---|
| `구간`, `달`, `역할` | 예측 구간, 평가 월, 역할 (`고르기` = 7월, `확인` = 8월, `시험` = 9월) |
| `후보`, `종류`, `손실` | 후보 이름 (예: `LSTM A`, `ENSEMBLE C`, `기준선 지난주`), 모델·앙상블·기준선 구분, 학습 손실 |
| `RMSE(kW)`, `MAE(kW)`, `공통C(kW)` | 오차 지표. 대표 선정에는 `공통C`를 쓴다 |
| `피크칸…` | 실제 전력이 피크 기준 b 이상인 칸에 대한 지표 (칸 수, 과소예측 평균, 재현율) |
| `기준선최고`, `…_개선율(%)` | 같은 구간·달에서 가장 좋은 기준선과, 그 대비 개선율 |
| `최고` | 대표 표시 (`A 최고`, `C 최고`) |

| `test_predictions/` | 최상위 `test_predictions/`와 같은 사본 |
| 그 밖의 CSV | `comparison*.csv` (7월 최고 조합 비교), `seed_*`·`ensemble.csv` (7월 시드 반복·앙상블), `confirm_*` (8월), `test_*` (9월), `final_seed_results.csv` (최종 모델의 시드별 8·9월 지표), `curves.csv` (학습 곡선), `README.md` (자동 생성 요약) |

`{설정해시}`는 설정값(JSON)의 MD5 앞 8자리이다. `grid_results.csv`와 `curves.csv`의 `2021-08` 행은 이전 설계(8월에도 그리드 검증)의 기록이며 코드가 읽지 않는다.

## 4. 실험 설계 요약

원자료는 2021-01-01 00:00부터 2021-09-14 23:45까지 15분 간격의 24,672행이다. 예측 대상은 `power_15min`(kW)이다. 예측 구간은 1h, 4h, 8h, 12h, 24h, 4d이며 시드는 42, 43, 44이다.

기간 분할은 1~6월 학습→7월 선정 검증, 1~7월 최종 모델 재학습→8월 확인 검증→9월 테스트로 고정했다. 테스트용으로 1~8월을 다시 학습하지 않는다. 대표 선정에는 공통 C 지표를 사용하고, 기본 안전마진은 7월 피크 근처 칸 오차의 95% 분위수로 정한다. 9월 테스트에서 대표·모델 설정·마진을 변경하지 않는다.

9월 테스트는 원자료가 끝나는 9월 14일까지(14일)이다. 4d는 하루에 한 번 발행하므로 9월 발행이 11개뿐이어서, 통계 검정 결과에 "표본 적음 — 해석 보류"로 표시된다.

미래 입력은 **다앎 조건**으로, 미래 시점의 실제 생산량·날씨를 사용한다. 완벽한 생산계획·날씨 예보를 아는 상황을 가정한 결과이다. 원자료에 테스트 실제값도 포함되어 있으므로 정해진 기간 분할을 유지한다.

8월 결과를 본 뒤 마진 방식(조건별 마진 → 기본 마진만)과 헛경보 집계 방식(발행 기준 → 대상 기준)을 조정한 이력이 있으며, `margin/조정기록.csv`에 남아 있다. 그리드 후보 범위는 이전 판의 7·8월 결과를 보고 정했다. 이전 판에서 9월 예측이 파일로 저장된 적은 있으나, 설정·대표·마진을 정하는 데에는 쓰지 않았다.

## 6. 설치 상세 및 오류 해결

Python 3.8 이상이 필요하다. 이 폴더에서 아래 방법 중 하나로 설치한다.

**방법 1 — 한 번에 설치**

```text
python -m pip install -r requirements.txt
```

**방법 2 — 패키지별 설치** (방법 1이 실패하면 어느 패키지에서 막히는지 확인할 수 있다)

```text
python -m pip install numpy
python -m pip install "pandas>=1.3"
python -m pip install "torch>=1.10"
python -m pip install scipy
python -m pip install matplotlib
```

- `>=`가 들어간 이름은 반드시 따옴표로 감싼다. 감싸지 않으면 cmd·PowerShell·bash 모두 `>`를 파일 저장으로 해석해 `=1.3` 같은 파일이 생기고 설치 조건이 무시된다.
- numpy·pandas·torch는 필수다. scipy는 선택이며, 없으면 통계 검정 p값을 정규 근사로 계산한다 (판정·마진·예측은 같고 p값 숫자만 조금 달라진다). matplotlib은 `main.py` 실행에 쓰이지 않으므로 설치가 실패하면 건너뛴다.
- 이미 조건을 만족하는 패키지(예: 서버에 설치된 GPU용 torch)는 다시 설치하지 않는다.

**GPU 사용 (선택)** — GPU가 없어도 CPU로 실행된다. Windows에서 위 명령으로 받는 기본 torch는 CPU용이다. CUDA GPU를 쓰려면 <https://pytorch.org/get-started/locally/> 에서 OS·CUDA 버전을 골라 나오는 명령으로 torch를 설치한다.

**설치 확인**

```text
python -c "import numpy, pandas, torch; print(numpy.__version__, pandas.__version__, torch.__version__, torch.cuda.is_available())"
```

오류 없이 버전이 출력되면 된다. 마지막 값이 `True`면 GPU, `False`면 CPU로 실행된다.

**가상환경 (선택)** — 다른 프로젝트와 패키지 버전이 섞이지 않게 하려면 먼저 가상환경을 만든 뒤 위 설치 명령을 실행한다.

```text
python -m venv .venv
.venv\Scripts\activate
```

Linux·macOS에서는 두 번째 줄 대신 `source .venv/bin/activate`를 실행한다.

**설치 오류 시**

| 증상 | 조치 |
|---|---|
| Windows에서 `python`을 찾을 수 없음 | `python` 대신 `py`를 쓴다 (`py -m pip install -r requirements.txt`, `py main.py`) |
| `Permission denied` / `액세스가 거부되었습니다` | 명령 끝에 `--user`를 붙이거나 가상환경을 사용한다 |
| `No matching distribution found for torch` | 설치된 Python 버전용 torch가 없는 경우. pytorch.org에서 지원 Python 버전을 확인하고 그 버전으로 가상환경을 만들어 설치한다 |
| `A module that was compiled using NumPy 1.x cannot be run in NumPy 2.x` | 오래된 torch가 이미 설치된 환경. `python -m pip install "numpy<2"` 실행 후 다시 실행한다 |
| PowerShell에서 `.venv\Scripts\activate`가 막힘 (스크립트 실행 불가) | 활성화하지 않고 `.venv\Scripts\python.exe -m pip install -r requirements.txt`, `.venv\Scripts\python.exe main.py`로 실행한다 |

개발 PC 환경 (참고, 이 환경에서 `--resume` 결과가 포함된 결과와 같음을 확인): Windows 11, Python 3.14.7, numpy 2.5.3, pandas 3.0.5, torch 2.14.0+cpu, scipy 1.18.1, matplotlib 3.11.2
