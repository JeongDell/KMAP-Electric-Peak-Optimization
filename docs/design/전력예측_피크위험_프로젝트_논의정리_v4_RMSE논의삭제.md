# 제조공정 전력사용량 예측 및 피크 위험 경보 프로젝트 정리

## 1. 문제 정의

### 목표
공장의 **과거 전력·생산·환경 정보**를 이용해 미래 전력사용량을 여러 시간 범위로 예측하고, 동시에 **높은 전력 사용(피크)이 발생할 확률**을 제공한다.

최종적으로는 단순히

> “앞으로 전력을 얼마나 사용할 것인가?”

만 예측하는 것이 아니라,

> “향후 일정 시간 안에 현재 최대수요전력 기준을 초과할 위험이 얼마나 되는가?”

까지 제공하는 것을 목표로 한다.

---

## 2. 데이터

KAMP 「자원 최적화 AI 데이터셋」을 사용한다.

- 기간: **2021-01-01 \~ 2021-09-14**
- 원 데이터: **6,168개 시간 단위 row**
- 주요 변수
  - 날짜 / 시간
  - `15분`, `30분`, `45분`, `60분` 최대수요전력
  - 생산량
  - 기온
  - 풍속
  - 습도
  - 강수량
  - 전기요금
  - 요일 / 월 / 일
  - 공장 인원
  - 인건비

전력은 변압기 센서에서 수집되었으며, 한 시간 안에 15분 단위로 4개의 최대수요전력 값이 존재한다.

### 전처리 방향

현재 데이터는 한 row에

```text
15분 / 30분 / 45분 / 60분
```

이 들어 있으므로 이를 아래와 같은 **15분 시계열**로 재구성한다.

```text
2021-01-01 00:00
2021-01-01 00:15
2021-01-01 00:30
2021-01-01 00:45
2021-01-01 01:00
...
```

따라서 약

```text
6168 × 4 = 24,672
```

개의 15분 시계열 포인트를 만들 수 있다.

## 3. 예측 시간 범위

예측은 **예측 Horizon**과 **업데이트 주기**를 구분해서 설계한다.

| 구분 | 예측 범위 | 예측 해상도 | 업데이트 |
|---|---:|---:|---:|
| 초단기 | 향후 1시간 | 15분 | 15분 |
| 중기 | 향후 4시간 | 15분 또는 1시간 | 1시간 |
| 중기 | 향후 8시간 | 1시간 | 1시간 |
| 중기 | 향후 12시간 | 1시간 | 1시간 |
| 일간 | 향후 24시간 | 1시간 | 1시간 |
| 장기 | 향후 3\~7일 | 1시간 또는 일 | 1일 |

예를 들어 초단기 예측은

```text
현재 시각 10:00

10:15 예상 전력
10:30 예상 전력
10:45 예상 전력
11:00 예상 전력
```

을 출력하고, **15분마다 다시 예측**한다.

## 4. 피크의 기준

피크 기준은 모델이 임의로 정하는 값이 아니라 **현재까지 알려진 최대수요전력 기준**으로 정의한다.

현재 논의한 기준은

```text
B(t) = max(M_current(t), M_reference(t))
```

이다.

### 이번 달 기준

```text
M_current(t) = max(이번 달 시작 ~ 현재 시점의 전력)
```

### 과거 기준

현재 프로젝트에서 정의한 전기요금 기준에 따라,

```text
M_reference(t) = max(직전 12개월의 1·2·7·8·9·12월 최대수요전력)
```

따라서 현재 피크 기준은

> **이번 달 현재까지 최대값과 과거 기준월 최대값 중 더 큰 값**

이다.

## 5. 피크 위험의 핵심 정의

우리가 궁극적으로 알고 싶은 것은

```text
P(Y(t+h) > B(t))
```

이다.

즉

> **미래 전력사용량이 현재 피크 기준을 초과할 확률**

이다.

예를 들어

```text
현재 기준전력 = 180 kW
1시간 후 예상 = 170 kW
```

라고 해도 불확실성이 크다면 피크 위험이 존재할 수 있다.

그래서 단순히

```text
170 < 180
→ 안전
```

이라고 판단하면 안 된다.

---

## 5. 피크 확률 계산 방식

현재 가장 적합하다고 판단한 방법은 **Quantile Forecasting**이다.

예를 들어 모델이 다음과 같이 예측했다고 하자.

| Quantile | 전력 |
|---:|---:|
| Q50 | 165 |
| Q70 | 175 |
| Q80 | 181 |
| Q90 | 190 |
| Q95 | 198 |

현재 피크 기준이

```text
B(t) = 180
```

이라면 180은 약 79\~80% Quantile에 해당한다.

따라서

```text
F(180) ≈ 0.80
```

이고

```text
P(Y > 180) ≈ 1 - 0.80 = 20%
```

로 볼 수 있다.

즉 기본적으로

```text
P_peak = 1 - F_hat(B(t))
```

을 사용한다.

### 7.1 P50, P90, P95가 의미하는 것

Quantile 예측에서 `P50`, `P90`, `P95`는 각각 미래 실제 전력값의 분포에서 특정 위치에 해당하는 예측값이다.

```text
P50 = Q0.50
P90 = Q0.90
P95 = Q0.95
```

예를 들어,

```text
P50 = 180 kW
P90 = 195 kW
P95 = 202 kW
```

라고 예측되었다고 하자.

모델이 잘 보정되어 있다는 전제에서 다음처럼 해석한다.

```text
P50 = 180 kW
→ 실제 전력이 180 kW 이하일 확률 ≈ 50%
→ 실제 전력이 180 kW를 초과할 확률 ≈ 50%

P90 = 195 kW
→ 실제 전력이 195 kW 이하일 확률 ≈ 90%
→ 실제 전력이 195 kW를 초과할 확률 ≈ 10%

P95 = 202 kW
→ 실제 전력이 202 kW 이하일 확률 ≈ 95%
→ 실제 전력이 202 kW를 초과할 확률 ≈ 5%
```

따라서 **P50은 대표적인 중심 예측값**, P90·P95는 **불확실성을 고려한 상단 위험 예측값**으로 본다.

### 7.2 P95는 p-value가 아니다

P95가 202 kW라고 해서

```text
피크가 발생할 확률 = 95%
```

라는 의미는 아니다.

P95는 **미래 전력값 분포의 95번째 분위수**이다.
즉, 미래 실제값이 P95 이하일 가능성이 약 95%가 되도록 예측한 값이다.

반면 p-value는 가설검정에서 사용하는 값으로,

> 귀무가설이 맞다고 가정했을 때 지금처럼 극단적인 데이터가 관측될 확률

을 의미한다.

따라서 두 개념은 용도가 다르다.

```text
P95        → 미래값 분포의 분위수 / 예측 상한 성격
p-value    → 통계적 가설검정용 확률
```

### 7.3 P95와 피크 경보의 관계

현재 피크 기준이 200 kW이고 예측 결과가 다음과 같다고 하자.

```text
P50 = 188 kW
P90 = 198 kW
P95 = 204 kW
피크 기준 B(t) = 200 kW
```

대표 예측값 P50만 보면

```text
188 < 200
```

이므로 피크가 예상되지 않는다.

하지만 P95는

```text
204 > 200
```

이므로 모델의 불확실성까지 고려하면 피크 기준에 도달할 가능성을 무시할 수 없다.

이 경우 시스템은

> **대표 예측값은 피크 미만이지만 상단 예측범위가 피크 기준을 넘으므로 피크 근접 사전경보**

를 제공할 수 있다.

단, `P95 > B(t)` 자체를 피크 확률로 사용하지 않는다.
실제 초과확률은 예측분포 전체를 이용해 별도로

```text
P(Y > B(t))
```

로 계산한다.

또한 P50·P90·P95의 확률 해석이 실제로 맞는지는 validation 데이터에서 **Quantile Coverage / Calibration**을 확인해야 한다.

## 5. 여러 시간 중 한 번이라도 피크가 발생할 확률

실제로 운영자가 더 궁금한 것은

> **“앞으로 4시간 안에 한 번이라도 피크가 발생할 확률”**

이다.

4시간을 15분 단위로 예측하면

```text
Y(t+1), Y(t+2), ..., Y(t+16)
```

이 존재한다.

우리가 원하는 것은

```text
P(max_{h=1,...,16} Y(t+h) > B(t))
```

이다.

### 단순 독립확률 계산은 피한다

다음과 같은 식

```text
1 - ∏_h (1 - p_h)
```

은 각 시점이 독립이라는 가정이 필요하다.

하지만 전력사용량은 인접 시간 사이의 상관성이 매우 높다.

따라서 최종적으로는 **미래 trajectory simulation** 방식을 사용하는 것이 적합하다.

---

## 5. Trajectory 기반 피크 확률

모델이 예측한 미래 분포에서 예를 들어 **1,000개의 미래 시나리오**를 만든다.

```text
Scenario 1
160 → 164 → 171 → ... → 176
Peak 없음

Scenario 2
166 → 173 → 182 → ... → 185
Peak 발생

Scenario 3
157 → 161 → 169 → ... → 175
Peak 없음
```

각 시나리오 `j`에 대해

```text
I_j = 1  if max_h Y_j(t+h) > B(t), otherwise 0
```

를 계산한다.

그다음

```text
P_peak,H = (1/N) × Σ_{j=1..N} I_j
```

로 피크 확률을 계산한다.

예를 들어 1,000개 중 237개 시나리오에서 피크가 발생하면

```text
P_4h_peak = 23.7%
```

이다.

## 5. 피크 근접 사전경보: 예측오차를 안전마진으로 활용

단순히 **예측값이 피크 기준을 넘었을 때만 경보**하면 실제 운영에서는 너무 늦을 수 있다.
특히 모델이 피크 구간에서 실제 전력을 과소예측할 가능성이 있기 때문에, **이전 피크값 근처에 접근한 단계부터 사전경보**를 제공해야 한다.

핵심 원칙은 다음과 같다.

```text
실제 피크 기준 B(t)       → 전기요금/운영 기준이므로 그대로 유지
모델의 과거 예측오차      → 피크 근접 경고를 위한 안전마진으로 활용
예측분포/Quantile         → 실제 피크 초과확률 계산에 활용
```

즉, **피크 기준 자체와 모델의 불확실성을 섞지 않고**, 불확실성을 별도의 경고 계층으로 사용한다.

### 10.1 단순 평균 오차율을 그대로 쓰지 않는 이유

처음 아이디어는 과거 예측값과 실제값의 차이를 퍼센트로 계산한 뒤, 그 오차율만큼 피크 기준보다 일찍 경고하는 방식이다.
방향은 타당하지만 **전체 평균 오차율 하나만 고정해서 사용하는 것은 권장하지 않는다.**

이유는 다음과 같다.

- 15분 후와 7일 후의 예측오차는 다르다.
- 생산량이 높은 시간과 일반 시간의 예측오차가 다를 수 있다.
- 교대시간, 고온, 동시가동 등 특정 조건에서 오차가 커질 수 있다.
- 피크 관리에서는 과대예측보다 **실제보다 낮게 예측하는 과소예측**이 더 위험하다.

따라서 일반적인 절대 퍼센트 오차보다 **과소예측 오차**를 중심으로 안전마진을 계산한다.

### 10.2 과소예측 오차란 무엇인가?

일반적인 예측오차를 다음처럼 정의할 수 있다.

```text
오차 e(t) = 실제값 y(t) - 예측값 y_hat(t)
```

예를 들어,

```text
실제 190 kW / 예측 170 kW
→ e(t) = +20 kW
→ 실제보다 20 kW 낮게 예측
→ 과소예측

실제 170 kW / 예측 190 kW
→ e(t) = -20 kW
→ 실제보다 20 kW 높게 예측
→ 과대예측
```

일반적인 MAE는 두 경우 모두 `20 kW 오차`로 동일하게 처리한다.

하지만 피크 관리에서는 두 오류의 위험이 다르다.

```text
과대예측
→ 실제보다 위험하게 본 것
→ 불필요한 경고가 발생할 수 있음

과소예측
→ 실제보다 안전하게 본 것
→ 실제 피크를 놓칠 수 있음
```

따라서 피크 경보에서는 **과소예측만 따로 분리해서 관리**한다.

과소예측오차를 다음처럼 정의한다.

```text
u(t) = max(0, 실제값 - 예측값)
```

예:

| 실제값 | 예측값 | 일반 절대오차 | 과소예측오차 u(t) |
|---:|---:|---:|---:|
| 190 | 170 | 20 | 20 |
| 170 | 190 | 20 | 0 |
| 200 | 185 | 15 | 15 |
| 185 | 185 | 0 | 0 |

즉, **실제값보다 낮게 예측했을 때만 양의 값**을 갖는다.

### 10.3 과소예측을 비율로 바꾸는 이유

단순히 `20 kW 틀렸다`만 보는 것보다 현재 피크 기준과 비교해서 어느 정도 위험한 오차인지 보는 것이 운영상 더 유용하다.

따라서 본 프로젝트에서는 다음 비율을 사용한다.

```text
과소예측 오차율 r⁺(t)
= max(0, 실제값 - 예측값) / 피크 기준 B(t)
```

예를 들어,

```text
피크 기준 B(t) = 200 kW
예측값          = 180 kW
실제값          = 194 kW
```

이면,

```text
과소예측오차 = 194 - 180 = 14 kW

r⁺(t) = 14 / 200
      = 0.07
      = 7%
```

이 값은

> **모델이 현재 피크 기준의 7%에 해당하는 크기만큼 실제 전력을 낮게 예측했다**

는 의미이다.

여기서 분모를 실제값이 아니라 피크 기준 B(t)로 두는 이유는 프로젝트의 핵심 목적이 단순 예측오차 분석이 아니라 **피크 위험 관리**이기 때문이다.

### 10.4 과거 과소예측오차를 어떻게 경보에 사용하는가?

validation 구간에서 모든 시점의 `r⁺(t)`를 계산한다고 하자.

예를 들어 다음과 같은 값들이 만들어질 수 있다.

```text
0%, 1%, 2%, 2%, 3%, 4%, 5%, 7%, 8%, 11%, ...
```

이 값들은

> **과거에 모델이 실제값보다 얼마나 낮게 예측했는가**

의 경험적 분포를 만든다.

예를 들어 이 분포의 분위수가 다음과 같다고 하자.

| 분위수 | 과소예측 오차율 |
|---|---:|
| P50 | 2.1% |
| P80 | 4.8% |
| P90 | 6.7% |
| P95 | 8.4% |

여기서 `과소예측오차 P95 = 8.4%`라는 뜻은

> 과거 validation 사례의 약 95%에서 과소예측오차율이 8.4% 이하였다는 의미

이다.

이는 `피크가 발생할 확률이 95%`라는 뜻이 아니다.

### 10.5 평균보다 상위 Quantile 오차를 사용하는 이유

안전마진은 평균 오차율보다 **상위 과소예측 오차 Quantile**을 사용하는 것이 적합하다.

예를 들어 과거 validation 결과가 다음과 같다고 하자.

| 과소예측 오차 분포 | 오차율 |
|---|---:|
| 50% Quantile | 2.1% |
| 80% Quantile | 4.8% |
| 90% Quantile | 6.7% |
| 95% Quantile | 8.4% |

95% 수준의 안전마진을 사용하면,

```text
m₀.₉₅ = 8.4%
```

이 값을 사용하는 이유는 단순히 평균적인 오차만 보는 대신, **과거 과소예측 사례 대부분을 포함할 수 있는 보수적인 오차 폭**을 사전경보에 반영하기 위해서다.

즉,

```text
실제 피크 기준 B(t) = 200 kW
과소예측오차 P95    = 8.4%
```

라면 모델이 과거처럼 실제값보다 낮게 예측할 수 있다는 점을 고려해 **200 kW에 도달하기 전에 경고를 시작**한다.

피크 근접 경고 기준은 다음과 같이 정의할 수 있다.

```text
경고 기준 W(t) = B(t) × (1 - m₀.₉₅)
```

피크 기준이 200 kW라면,

```text
W(t) = 200 × (1 - 0.084)
     = 183.2 kW
```

따라서 운영 규칙을 다음처럼 만들 수 있다.

```text
예측값 < 183.2 kW        → 정상 영역
183.2 ≤ 예측값 < 200 kW → 피크 근접 경고 영역
예측값 ≥ 200 kW          → 피크 예상 영역
```

### 10.6 Quantile Forecast와 결합

오차 기반 안전마진보다 한 단계 더 통계적으로 자연스러운 방법은 **예측분포의 상한 Quantile이 피크 기준에 도달하는지 확인하는 것**이다.

예를 들어,

| 예측값 | 전력 |
|---|---:|
| P50 | 188 kW |
| P90 | 198 kW |
| P95 | 204 kW |
| 피크 기준 B(t) | 200 kW |

이면 중앙 예측값은 200 kW보다 낮지만 P95가 200 kW를 초과한다.

```text
P50 = 188 < 200
P95 = 204 > 200
```

여기서 P50은

```text
실제 전력이 188 kW 이하일 가능성 ≈ 50%
실제 전력이 188 kW보다 높을 가능성 ≈ 50%
```

이라는 의미의 중앙값 예측이다.

반면 P95는

```text
실제 전력이 204 kW 이하일 가능성 ≈ 95%
실제 전력이 204 kW보다 높을 가능성 ≈ 5%
```

이라는 의미의 상단 분위수 예측이다.

따라서

> 평균적으로는 피크가 예상되지 않지만, 예측 불확실성을 고려하면 피크 도달 가능성이 있으므로 사전경보

로 판단한다.

실제 시스템에서는 다음 두 정보를 함께 사용한다.

```text
Peak 접근도 = 대표 예측값 / B(t)
Peak 초과확률 = P(Y > B(t))
```

예를 들어,

```text
대표 예측값    = 188 kW
피크 기준      = 200 kW
Peak 접근도    = 94%
Peak 초과확률  = 18%
```

이라면 **“현재 예상값은 기존 피크의 94% 수준이며, 불확실성을 고려한 피크 초과확률은 18%”**처럼 해석할 수 있다.

### 10.7 Horizon별 안전마진

예측 시간이 길어질수록 불확실성이 커지므로 **모든 horizon에 동일한 오차율을 적용하면 안 된다.**

예를 들어 validation 결과가 다음과 같다면,

| Horizon | 95% 과소예측 오차 |
|---|---:|
| +15분 | 3% |
| +1시간 | 5% |
| +4시간 | 7% |
| +12시간 | 10% |
| +24시간 | 12% |
| +3일 | 17% |
| +7일 | 23% |

각 horizon의 경고 기준은 다음처럼 달라진다.

```text
W(t,h) = B(t) × (1 - m(h))
```

즉, **장기예측일수록 더 넓은 안전마진을 사용하고 더 일찍 사전경보를 제공한다.**

### 10.8 생산조건별 Dynamic Safety Margin

프로젝트의 또 다른 목표는 **예측오차가 크게 발생하는 생산조건을 찾는 것**이다.
이 분석 결과를 경보 시스템에 직접 연결할 수 있다.

예를 들어,

| 생산조건 | 95% 과소예측 오차 |
|---|---:|
| 일반 생산 | 5% |
| 고생산량 | 9% |
| 교대시간 | 11% |
| 고온 + 고생산량 | 14% |

이라면 안전마진을 다음과 같이 조건부로 정의할 수 있다.

```text
m = m(horizon, 생산량, 시간대, 교대조건, 기상조건, ...)
```

피크 기준이 200 kW일 경우,

```text
일반 상황        : 200 × (1 - 0.05) = 190 kW부터 경고
교대 + 고부하    : 200 × (1 - 0.11) = 178 kW부터 경고
고온 + 고생산량  : 200 × (1 - 0.14) = 172 kW부터 경고
```

이렇게 하면 **“예측오차가 큰 조건 분석”이 단순 사후 분석으로 끝나지 않고 실제 경보 민감도 조절에 사용된다.**

### 10.9 최종 경보 체계

경보는 **실제 피크 판정**과 **사전 위험 경보**를 분리한다.

| 단계 | 판단 기준 | 의미 |
|---|---|---|
| 정상 | 예측분포가 피크 기준과 충분히 떨어져 있음 | 현재 위험 낮음 |
| 피크 근접 | 안전마진 기준 W(t,h)에 진입 또는 상위 Quantile이 B(t)에 근접 | 생산·설비 일정 확인 |
| 피크 위험 | P(Y > B(t))가 설정된 위험확률 이상 | 부하 분산/가동 조정 필요 |
| 피크 예상 | 대표 예측값 자체가 B(t) 이상 | 즉각적인 대응 필요 |

경보 확률 임계값(예: 20%, 50%, 80%)은 현재 단계에서 임의로 고정하지 않고, **validation에서 False Negative 비용과 경보 빈도를 함께 평가해 결정**한다.

### 10.10 최종 권장 방식

두 접근법 중 하나를 선택하는 것이 아니라 다음처럼 역할을 분리해 함께 사용하는 것이 가장 적합하다.

```text
[과거 오차 기반 Safety Margin]
→ 피크에 가까워지기 전에 조기에 경고하기 위한 운영용 버퍼

[Quantile / Peak Probability]
→ 미래 전력이 실제 피크 기준을 초과할 확률을 정량적으로 제공
```

따라서 최종 프로젝트의 피크 위험 엔진은 다음 세 값을 중심으로 구성한다.

```text
1. 실제 피크 기준 B(t)
2. Dynamic Safety Margin 기반 근접 경고 기준 W(t,h)
3. Peak 초과확률 P(Y > B(t))
```

## 5. 왜 일반적인 MSE/RMSE만으로는 부족한가?

이 문제에서는 **평균적으로 잘 맞는 것만으로 부족하다.**

예를 들어 시간 구간별 RMSE가

```text
5.2
4.8
5.5
4.9
5.1
18.7
```

이라면 전체 RMSE는 상대적으로 괜찮아 보일 수 있지만, 특정 구간에서 예측이 완전히 실패한다.

공장 전력 예측에서는 이런 구간이 실제 **피크 발생 구간**일 수 있기 때문에 매우 위험하다.

따라서 목표는

> 전체 오차가 작으면서 동시에 **특정 시간구간에서 오차가 폭발하지 않는 모델**

이다.

## 5. Loss Function 설계

최종적으로 다음 3가지 목적을 동시에 고려한다.

```text
1. 전체 예측 오차 최소화
2. 특정 구간의 큰 오차 억제
3. Peak 구간에서의 과소예측 억제
```

### 12.1 평균 구간 Loss

시간을 여러 window로 나누고 각 window의 RMSE를

```text
R_k = sqrt((1 / |W_k|) × Σ_{t∈W_k} (y_t - ŷ_t)^2)
```

라고 한다.

전체적인 정확도는

```text
L_mean = (1/K) × Σ_k R_k
```

로 본다.

---

## 5. CVaR Loss

전체 window 중 **예측이 가장 나쁜 상위 20%의 평균 오차**를 계산한다.

```text
L_CVaR = Mean(Worst 20% Window RMSE)
```

CVaR는 단순히 구간별 오차 분산을 줄이는 것이 아니라 **가장 나쁜 구간 자체를 직접 줄이는 것**이 목적이다.

---

## 5. Peak Underprediction Loss

전력 피크 문제에서는

```text
실제 190
예측 160
```

같은 **과소예측**이 특히 위험하다.

따라서

```text
u_t = max(0, y_t - ŷ_t)
```

를 정의하고, 현재 피크 기준 `B(t)` 근처에서는 가중치를 증가시킨다.

```text
L_peak = (1/N) × Σ_t (w_t × u_t^2)
```

---

## 5. 최종 Risk-aware Loss

Neural Network 계열에서는 기본적으로

```text
L = α·L_mean + β·L_CVaR + γ·L_peak
```

를 사용한다.

초기 실험값은 예를 들어

```text
L = 0.5·L_mean + 0.3·L_CVaR + 0.2·L_peak
```

로 시작한다.

이 비율은 validation을 통해 최종 조정한다.

---

## 5. Loss 실험 단계

### Loss A — Baseline

```text
L_A = MSE
```

### Loss B — 안정성 고려

```text
L_B = 0.6·L_mean + 0.4·L_CVaR
```

### Loss C — 최종 목표

```text
L_C = 0.5·L_mean + 0.3·L_CVaR + 0.2·L_peak
```

## 5. 모델별 Loss 적용 방법

### Random Forest

Random Forest는 custom differentiable loss를 직접 적용하기 어렵다.

따라서

```text
1차 학습
→ window별 RMSE 계산
→ 오차 큰 window에 sample weight 증가
→ 재학습
```

방식을 사용한다.

### LightGBM / CatBoost

Boosting 계열 역시 CVaR를 직접 objective에 넣기보다는

```text
w_t = w_bad_window × w_peak
```

형태의 sample weight를 적용한다.

즉

```text
L = Σ_t w_t (y_t - ŷ_t)^2
```

형태의 **Weighted MSE**로 CVaR 효과를 간접 구현한다.

### SimpleRNN / LSTM / GRU

직접 custom loss 적용이 가능하다.

```text
L = 0.5·L_mean + 0.3·L_CVaR + 0.2·L_peak
```

### N-HiTS / N-BEATS / DLinear

Multi-horizon output을 직접 학습하므로 Risk-aware Loss 적용이 자연스럽다.

```text
[ŷ(t+1), ŷ(t+2), ..., ŷ(t+H)]
```

전체에 대해

```text
L_mean + L_CVaR + L_peak
```

를 계산한다.

## 5. 확률예측을 위한 Quantile Loss

최종적으로 피크 확률을 계산하기 위해서는 단순 point prediction만으로 부족하다.

따라서 상위 모델은 다음 Quantile을 예측한다.

```text
Q0.05, Q0.10, Q0.20, Q0.50, Q0.80, Q0.90, Q0.95
```

Quantile 예측에는 **Pinball Loss**를 사용한다.

```text
Pinball Loss at quantile τ:
- if y ≥ ŷ:  L_τ = τ × (y - ŷ)
- if y < ŷ:  L_τ = (1 - τ) × (ŷ - y)
```

이를 통해 미래 전력의 분포를 추정한다.

- Quantile Coverage

예를 들어 모델이 `Peak 확률 = 70%`라고 예측한 사례 중 실제 약 70%에서 피크가 발생해야 좋은 확률모델이다.

---

## 5. 현재 데이터의 중요한 한계

현재 데이터는 **2021년 1월\~9월 약 9개월**이다.

하지만 실제 피크 기준은 직전 **12개월** 정보가 필요하다.

따라서 현재 KAMP 데이터만으로는 실제 요금 기준을 완전히 재현할 수 없다.

실험 단계에서는

```text
1. 초기 Peak 기준을 별도로 설정하거나
2. 확보 가능한 과거 데이터 범위 내의 rolling maximum을 사용
```

해야 한다.

실제 현장 적용에서는 **최소 12개월 이상의 전력 이력**이 필요하다.

## 5. 현재까지의 핵심 결정 사항

1. **15분 시계열로 재구성**
2. **단기·중기·장기 Multi-horizon forecasting**
3. **현재까지 최대수요전력에 기반한 Dynamic Peak Threshold**
4. **RMSE를 직접 Peak threshold에 더하지 않음**
5. **Point forecast가 아니라 Quantile/확률 예측 수행**
6. **Peak 확률 = `P(Y > B(t))`**
7. **여러 시간의 Peak 위험은 trajectory simulation으로 계산**
8. **일반 MSE 외에 Worst-window CVaR Loss 사용**
9. **Peak 과소예측에 추가 penalty**
10. **Random Forest / SimpleRNN은 KAMP baseline**
11. **LightGBM / CatBoost / N-HiTS / LSTM / DLinear 우선 실험**
12. **최종적으로 상위 모델 Ensemble**
13. **실제 피크 기준 B(t) 자체에는 예측오차를 더하거나 빼지 않음**
14. **과거 과소예측 오차의 상위 Quantile로 Dynamic Safety Margin 구성**
15. **Horizon 및 생산조건별로 피크 근접 경고 기준 W(t,h)를 다르게 설정**
16. **P50은 중앙값 예측으로, 실제값이 그보다 낮거나 높을 가능성이 각각 약 50%인 지점으로 해석**
17. **P90/P95는 미래값 분포의 상단 분위수이며 p-value와 다른 개념**
18. **과소예측오차는 max(0, 실제값-예측값)으로 정의하고 피크 기준 대비 비율로 정규화**
16. **Peak 접근도 + Peak 초과확률 + 피크 근접 경보를 함께 제공**

## 28. 프로젝트의 핵심 아이디어 한 문장

> **과거 전력·생산·환경 데이터를 이용해 단기부터 장기까지 미래 전력사용량의 확률분포를 예측하고, 과거 과소예측 오차를 기반으로 horizon·생산조건별 안전마진을 설정해 기존 피크값 근처부터 조기경보를 제공하며, 실제 피크 기준 초과확률까지 함께 산출하는 Risk-aware AI 시스템을 구축한다.**

### 핵심 수식

예측:

```text
Ŷ(t+1 : t+H)
```

피크 기준:

```text
B(t) = max(이번 달 현재까지 최대전력, 과거 기준 최대전력)
```

시점별 피크 확률:

```text
P(Y(t+h) > B(t))
```

기간 내 피크 확률:

```text
P(max_{h≤H} Y(t+h) > B(t))
```

최종 Loss:

```text
L = 0.5·L_mean + 0.3·L_CVaR + 0.2·L_peak
```

이 네 개가 현재 프로젝트의 중심 구조이다.
